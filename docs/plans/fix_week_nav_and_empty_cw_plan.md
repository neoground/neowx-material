# Plan: Fix Month-to-Week Navigation Context & Empty Current Week Archive Data

## 1. Root Cause Analysis

### Issue 1: Switching from Current Month (`month-YYYY-MM.html`) to Week jumps to the 1st of the Month's Week (e.g. CW 44 instead of CW 47)
In `bin/user/neowx_archive.py` inside `_build_nav_context` (lines 713–719):
```python
elif summarize_by == 'SummaryByMonth':
    context_month_link = f"{base_path}archive/{context_year_str}/months/month-{context_year_str}-{context_month_str}.html"
    first_day_mo = datetime.date(yr, mo, 1)
    mo_wk = first_day_mo.isocalendar()[1]
    context_week_link = f"{base_path}archive/{context_year_str}/weeks/week-{context_year_str}-{mo_wk:02d}.html"
    target_day = stop_day if is_current_month else 1
    context_day_link = f"{base_path}index.html" if is_current_month else f"{base_path}archive/{context_year_str}/days/day-{context_year_str}-{context_month_str}-{target_day:02d}.html"
```
- Unlike `SummaryByYear` (which checks `is_current_year`) and `context_day_link` in `SummaryByMonth` (which checks `is_current_month`), `context_week_link` in `SummaryByMonth` **unconditionally** uses `datetime.date(yr, mo, 1).isocalendar()[1]`.
- For November 2026 (`2026-11-01`, Sunday), the ISO week is **CW 44**, so clicking "Week" from the current month jumps to `week-2026-44.html` instead of the current week (`stop_iso_wk`, CW 47).
- Additionally, for historical months (`not is_current_month`), if the 1st of the month falls on a Friday/Saturday/Sunday (e.g. `2026-11-01` or `2027-01-01`), `first_day_mo.isocalendar()` belongs to the previous month's (or even previous year's) ISO week, and week filenames in `neowx_archive.py` are generated using the week's **Monday** year (`%Y-%V` of `timespan.start`).

### Issue 2: Current Week (`week-2026-47.html` on `wetterbrienz.ch`) shows no weather data (cards/charts empty), while `week-2026-46.html` shows this week's data
1. **Why it happens (`week_start` mismatch between `genWeekSpans` and WeeWX `TimeBinder.week`):**
   - `NeowxArchiveGenerator` generates `SummaryByWeek` files using `genWeekSpans(start_ts, stop_ts)`, which yields **ISO Monday-to-Monday** `TimeSpan`s (`startOfWeek = 0`):
     - For `week-2026-46.html`: `timespan` is `[Mon 2026-11-09 00:00, Mon 2026-11-16 00:00]`.
     - For `week-2026-47.html`: `timespan` is `[Mon 2026-11-16 00:00, Mon 2026-11-23 00:00]`.
   - However, when WeeWX's `Stats` search-list extension creates `TimeBinder` (`$week` in `week-%Y-%V.html.tmpl`), it passes `timespan.stop` as `report_time` and `self.generator.stn_info.week_start` as `startOfWeek` (which defaults to **`6` = Sunday** in `weewx.conf` unless overridden):
     ```python
     # In weewx/tags.py:
     def week(self, data_binding=None, weeks_ago=0):
         week_start = to_int(self.option_dict.get('week_start', 6))
         return TimespanBinder(
             weeutil.weeutil.archiveWeekSpan(self.report_time, startOfWeek=week_start, weeks_ago=weeks_ago), ...)
     ```
   - When `week_start = 6` (Sunday) on the station:
     - For **CW 47**, `timespan.stop` is **Mon 2026-11-23 00:00**. `archiveWeekSpan(Mon Nov 23 00:00, startOfWeek=6)` computes the Sunday-to-Sunday week containing Nov 23, which is **`[Sun 2026-11-22 00:00 -> Sun 2026-11-29 00:00]`**!
     - Because today is **Wed 2026-11-18**, the entire span `[Nov 22 -> Nov 29]` is in the **future**! Thus `$week.<obs>.has_data` is `False` for every sensor on `week-2026-47.html`, and only static/embedded items render.
     - Meanwhile, for **CW 46**, `timespan.stop` is **Mon 2026-11-16 00:00**, so `archiveWeekSpan(Mon Nov 16 00:00, startOfWeek=6)` computes `[Sun 2026-11-15 00:00 -> Sun 2026-11-22 00:00]`, which actually contains Sunday Nov 15 through Wednesday Nov 18 (as visible on `wetterbrienz.ch`'s CW 46 cards: `Mi 18 11:57`).

## 2. Proposed Changes

### A. Fix `TimeBinder` `week_start` in `bin/user/neowx_archive.py`
- Because `SummaryByWeek` and all ISO week URLs/pickers in `neowx-material` are strictly ISO-8601 weeks (`%V`, Monday-to-Monday, generated by `genWeekSpans`), `$week` inside templates **must** use `week_start = 0` (Monday) so that `archiveWeekSpan(timespan.stop, startOfWeek=0)` matches the exact Monday-to-Monday `TimeSpan` generated by `genWeekSpans`.
- In `NeowxArchiveGenerator._getSearchList` (or by overriding `_getSearchList` in `NeowxArchiveGenerator`), ensure any `TimeBinder` instance in the search list has `option_dict['week_start'] = 0` (or set `self.stn_info.week_start = 0` / update `TimeBinder.option_dict` when `summarize_by == 'SummaryByWeek'` or globally for the skin).
- Also bump `MIN_ARCHIVE_VERSION['SummaryByWeek']` in `bin/user/neowx_archive.py` to `'2.1.5'` (or the next version) so existing miscalculated historical `week-YYYY-WW.html` files (like `week-2026-46.html` on stations with `week_start = 6`) are automatically regenerated during Pass 2 backfill!
- Bump `VERSION` in `bin/user/neowx_archive.py` (from `"1.2.0"` to `"1.2.1"`).

### B. Fix `context_week_url` in `bin/user/neowx_archive.py` (`_build_nav_context`)
- In `SummaryByMonth`:
  - When `is_current_month` is `True`, point `context_week_link` to `current_week_url` (i.e. the current week `stop_iso_wk`, CW 47).
  - When `is_current_month` is `False` (historical month), choose the first ISO week whose Monday is in that month (or the week of the 1st of the month if clamped to `[start_dt, stop_dt]`), and format its path using the Monday's year and `%V` so it always matches the filename generated by `genWeekSpans` (which uses `timespan.start`, i.e., Monday).
- Also verify `SummaryByWeek` and `SummaryByDay` when a week spans across a year/month boundary so `context_week_link` always uses the week Monday's year (`ref_monday.strftime('%Y')` and `ref_monday.strftime('%V')`).

### C. Fix PR #422 Review Findings for Earthquakes Component
1. **`skins/neowx-material/js/earthquakes.js`**:
   - **Targeted `moveend` listener removal**: Track `pendingMoveEnd` inside `populateMapAndList` and call `map.off('moveend', pendingMoveEnd)` instead of `map.off('moveend')` so Leaflet's internal renderer and tile layer listeners remain intact.
   - **Lazy `#neowx-popup` modal resolution**: Resolve `modal = mount.closest('.modal')` inside the `neowxOpenPopup` `onShown` callback and add `.nwm-popup-earthquakes` before creating the Leaflet map so first-time popup expansion gets the proper dimensions.
   - **Refresh active popup modal when async requests settle**: Track loading/error state (`isLoading`, `loadError`) and active popup state (`activePopupUpdater`), updating the open modal if the USGS earthquake or fault line fetch settles or errors while the modal is open.
   - **Preserve `0` minimum magnitude / numeric coordinates**: Parse `stationLat`, `stationLon`, `radiusKm`, `minMag`, and `timespanDays` with explicit `isNaN(...)` fallbacks so `min_magnitude = 0` is not replaced with `2.5`.
   - **Include `timespanDays` in `cacheKey`**: Append `'_' + timespanDays` to `neowx_earthquakes_cache_...` in `localStorage`.
2. **`skins/neowx-material/css/earthquakes.css`**:
   - Remove `.auto-theme .leaflet-popup-content` from the unconditional rule at the bottom of the stylesheet so light-mode `auto-theme` popups keep readable `#212121` dark text on white backgrounds (dark-mode `auto-theme` is already handled inside `@media (prefers-color-scheme: dark)`).
3. **`skins/neowx-material/inc/head.inc` & `skins/neowx-material/inc/js.inc`**:
   - Load earthquake CSS and JS based on whether the current page's recognized layout items (`$panelItems(page=$getVar('page', None), subpage=$getVar('subpage', None))`) include any `earthquake*` item (with fallback if `panelItems` is unavailable).
